# INCY для iOS 12.5.8

VPN-клиент для iPhone 6 и других iPhone с архитектурой arm64. Минимальная
версия системы в проекте — iOS 12.5. Приложение написано на Swift/UIKit;
расширение `PacketTunnel` передаёт трафик через `hev-socks5-tunnel` в Xray.

## Что уже реализовано

- Профили VLESS, включая REALITY и Vision, VMess AEAD, Trojan,
  Shadowsocks/SS2022, SOCKS5 и HTTP-прокси.
- Импорт ссылок, списков ссылок, HTTPS-подписок и QR-кодов.
- gRPC в режимах `gun` и `multi`, с TLS или VLESS REALITY и отдельным `authority`.
- В смешанной подписке добавляются совместимые серверы; пропуски показываются
  с причинами. Ошибки формата, ключей и состояния подписки останавливают импорт.
- Выбор, переименование и удаление профилей; хранение ключей в Keychain.
- Подключение VPN, счётчики трафика и выбор DNS-сервера.
- До включения маршрутов проверяется доступность сервера и реальный HTTP-ответ
  через выбранный прокси. Имя сервера разрешается до перенаправления DNS в VPN;
  TLS SNI, Host и gRPC authority сохраняются, исходный профиль не изменяется.
- При ошибке подключения приложение показывает причину на iOS 12. Диагностика
  содержит этап запуска и счётчики пакетов без ключей и ссылок подписки.
- Отдельные цели Xcode для приложения и VPN-расширения.

На iOS 12 обработчик HEV соединяется с Xray через IPv6 loopback `::1`.
Соединение из IPv6-сокета с IPv4-mapped `127.0.0.1` после включения VPN
могло завершаться `EADDRNOTAVAIL` (errno 49): VPN включался, но сайты не загружались.
TCP и UDP используют `::1`; IPv4 loopback остаётся отдельным локальным входом.
Проверка реального ответа через прокси выполняется до и после настройки маршрутов.
Это внутреннее соединение и не требует IPv6 у интернет-провайдера.
Рабочее состояние build 10 и результаты проверки записаны в [SESSION_NOTES.md](SESSION_NOTES.md).

## Сборка через GitHub Actions

1. Откройте [Actions → iOS Build](https://github.com/nabivkubkov-prog/VPN-IOS-12.5.8/actions/workflows/ios-build.yml).
2. Нажмите **Run workflow** и выберите ветку с исправлениями сборки:
   `codex/ios-github-build`, пока они не перенесены в `main`.
3. Дождитесь завершения запуска. Workflow проверяет Swift-профили и
   конфигурации Xray, HTTP-передачу через gRPC, таймаут и отмену проверки
   соединения, собирает нативные библиотеки и архив приложения,
   затем проверяет архитектуру, минимальную iOS и отсутствие обязательной
   зависимости от SwiftUI в обоих исполняемых файлах.
4. В разделе **Artifacts** скачайте `INCY-iOS-12.5.8-unsigned` и распакуйте
   ZIP. Внутри находится `INCY-iOS-12.5.8-unsigned.ipa` с VPN-расширением.

Запуск из GitHub CLI:

```powershell
gh workflow run ios-build.yml --repo nabivkubkov-prog/VPN-IOS-12.5.8 --ref codex/ios-github-build
gh run list --repo nabivkubkov-prog/VPN-IOS-12.5.8 --workflow ios-build.yml
```

IPA собирается без подписи. Для установки и работы VPN на обычном iPhone
нужно подписать приложение и расширение профилями Apple Developer с
возможностью Network Extensions и общей группой Keychain. На устройстве
с джейлбрейком способ установки зависит от используемого джейлбрейка.

Сообщение `permission denied` при настройке VPN обычно означает, что
установленная копия не получила разрешение Network Extensions. Бесплатная
подпись Apple ID через iLoader не предоставляет это разрешение. Для обычного
iPhone нужны подходящие профили участника Apple Developer Program для обеих
целей; пересборка исходников сама по себе не выдаёт права подписи.

При импорте лимит 1 МБ относится к полученному списку серверов. Ошибки
сервера, например HTTP 403 или 404, отображаются отдельно с HTTP-кодом.

Для подписок с ограничением числа устройств INCY передаёт стандартные
заголовки `x-hwid`, `x-device-os`, `x-ver-os` и `x-device-model`. Идентификатор
случайно создаётся один раз для этой установки и сохраняется при обновлении
приложения. Повторный импорт использует тот же идентификатор; лимит устройств
сервиса учитывается. Вставляйте личную ссылку подписки из бота VPN-сервиса.
Служебные ответы вроде `App not supported` и превышения лимита устройств
отображаются как ошибки, а не добавляются в список серверов.

Версия для iOS 12 использует User-Agent `INCY-iOS12/1.0`, чтобы серверы
Remnawave выдавали списки ссылок, в том числе Base64, без переключения на
полные Xray JSON-конфигурации для современных клиентов `INCY/`. Если сервер
всё же прислал JSON или веб-страницу, приложение объясняет формат ответа
вместо сообщения о слишком длинной ссылке.

## Сборка для джейлбрейка

При ручном запуске workflow включите **jailbreak**, чтобы получить ещё один
артефакт `INCY-iOS-12.5.8-jailbreak` с файлом `INCY-iOS-12.5.8-jailbreak.ipa`.
Либо запустите:

```powershell
gh workflow run ios-build.yml --repo nabivkubkov-prog/VPN-IOS-12.5.8 --ref codex/ios-github-build -f jailbreak=true
```

Этот вариант отображается на телефоне как **INCY JB** и использует отдельный
идентификатор `app.incy.legacy.jailbreak`. Его можно установить рядом с INCY
из iLoader; профили серверов нужно импортировать заново.

Workflow подписывает расширение и приложение ad-hoc, сохраняя разрешение
`packet-tunnel-provider`, `allow-vpn` и одну общую группу Keychain. Подпись
содержит application-identifier с префиксом `INCYJB0001`, чтобы NetworkExtension
мог определить идентификатор приложения при обмене сообщениями с расширением.
Это техническое пространство имён для ad-hoc, а не команда Apple Developer.
Переменные Xcode в
entitlements заменяются конкретными значениями; подписи и встроенные права
обоих компонентов проверяются перед упаковкой. Подпись ad-hoc предназначена
для джейлбрейка и не является профилем Apple Developer.

Для установки нужны активный джейлбрейк с поддержкой этих прав и
[AppSync Unified из источника автора](https://github.com/akemin-dayo/AppSync/releases/tag/116.0).
В релизе AppSync вариант `iphoneos-arm` предназначен для rootful, а
`iphoneos-arm64` — для rootless; название пакета здесь не определяет CPU.
На Amethyst с rootful bootstrap используется `iphoneos-arm`.

Установите jailbreak IPA через совместимый установщик AppSync, например
Filza или `ideviceinstaller`. Повторная подпись через iLoader может снова
заменить права VPN правами бесплатного provisioning profile. AppSync
позволяет установить пакет, а права VPN находятся в подписи самого IPA.
Сборка проверяет подпись и совместимость бинарников; подключение к серверу
необходимо отдельно проверить на телефоне.

## Локальная сборка на Mac

Нужны Xcode с iPhoneOS SDK и Go **1.22.12**. Версию Go фиксируем для
совместимости со старой iOS; обновлять её автоматически нельзя.

```bash
git clone --branch codex/ios-github-build --recurse-submodules https://github.com/nabivkubkov-prog/VPN-IOS-12.5.8.git
cd VPN-IOS-12.5.8
bash Scripts/check-macos.sh
```

В существующей копии проекта сначала выполните
`git submodule update --init --recursive`. Ревизия библиотеки туннеля
закреплена в Git; `Scripts/build-core.sh` проверяет её перед сборкой.

Для подписанной сборки задайте уникальный `INCY_BUNDLE_BASE` и свой
`DEVELOPMENT_TEAM` в `Config/Signing.xcconfig`, настройте подпись обеих
целей в Xcode и соберите схему `INCY`. Windows подходит для редактирования
проекта и запуска GitHub Actions; компиляция iOS выполняется на Mac.
